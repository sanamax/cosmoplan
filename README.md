# Orbital OKR — цели компании в 3D

Интерактивная система управления целями, проектами и задачами в виде космоса.
Руководитель видит исполнение **Задач** внутри **Проектов**, Проектов внутри **Целей**, Целей внутри
**Компаний**, а Компаний — внутри **Группы компаний**. Прогресс исполнения считается автоматически
снизу вверх и отображается в 3D-сцене, дереве и отчётах.

* Группа компаний — скопление вселенных
* Компания — вселенная (светящееся ядро, спиральные рукава, звёздная пыль)
* Цель — галактика с Солнцем в центре
* Проект — планета (зона ответственности руководителя)
* Задача — спутник планеты
* Подзадача — спутник спутника

---

## 1. Запуск

### Вариант 1 — двойной клик (офлайн, `file://`)

Откройте **`index.html`** двойным кликом. Приложение полностью работает с `file://`:
все библиотеки лежат локально в `libs/`, код написан на классических `<script>` (без ES-модулей
и `fetch`), шрифты — системные (`Inter` / `PT Sans` / `Segoe UI` с fallback), интернет не требуется.

### Вариант 2 — локальный сервер

```bash
cd cosmoplan
python -m http.server 8080
# затем откройте http://localhost:8080
```

Любой другой статический сервер (`npx serve`, nginx, Apache) тоже подходит: сборка не требуется.

**Требования:** современный браузер с WebGL (Chrome, Edge, Firefox, Safari 14+), разрешение от 1024 px.
Рекомендуется 1280 px и больше.

## 3. Модель данных

Каждый объект иерархии хранится в `localStorage` под ключом `orbital-okr:data` и описывается структурой:

| Поле | Описание |
|---|---|
| `id` | уникальный идентификатор: `GRP-000001`, `CMP-000001`, `GOAL-000001`, `PRJ-000001`, `TSK-000001`, `SUB-000001` |
| `type` | `group` \| `company` \| `goal` \| `project` \| `task` \| `subtask` |
| `parentId` | идентификатор родителя (ровно один; у корневой Группы — `null`) |
| `name` | название (редактируется в карточке) |
| `description` | «Описание цели» — многострочный редактируемый комментарий |
| `status` | `новая` \| `в работе` \| `выполнено` \| `риск` \| `на паузе` |
| `progressMode` | `manual` (ползунок прогресса) \| `recurring` (повторяющаяся задача) |
| `progress` | ручной прогресс 0–100 |
| `kind` | тип свойства: `задача`, `подзадача`, `делегировано`, `автоматизировано`, `связан`, `проблема`, `отчёт` |
| `color` | цвет в hex, тонирует фактуру и кольца |
| `texture` | одна из 16 фактур (`earth`, `mars`, `jupiter`, `saturn`, `venus`, `mercury`, `moon`, `neptune`, `uranus`, `lava`, `ice`, `gas`, `desert`, `ocean`, `crystal`, `tech`) |
| `size` | радиус объекта в единицах сцены |
| `orbitRadius` | диаметр орбиты (расстояние от родителя); `0` = авто-раскладка |
| `responsible` | `{ fio, role, function }` — ответственный (ФИО, роль, функция) |
| `executor` | `{ fio, role, function }` — исполнитель (ФИО, роль, функция) |
| `dueDate` | срок исполнения `YYYY-MM-DD` |
| `automationLinks` | `[{ title, url }]` — гиперссылки на автоматизацию |
| `links` | `[{ id, flow }]` — связи с объектами того же уровня; `flow`: `out` (энергия к объекту), `in` (от объекта), `both` (в обе стороны) |
| `createdAt`, `updatedAt` | ISO-метки времени |

Дополнительно хранятся: выбранный вид, позиция камеры (для каждого вида), раскрытые узлы дерева,
скорость вращения и состояние паузы, счётчики ID.

### Правила расчёта прогресса

1. **Подзадача** — прогресс задаётся вручную ползунком 0–100 %.
2. **Задача**: есть подзадачи → среднее арифметическое их прогресса (ползунок заблокирован и показывает
   расчётное значение); нет подзадач → ручной ввод.
3. **Проект** = среднее прогресса его Задач.
4. **Цель** = среднее прогресса её Проектов (единое правило для всех уровней: среднее **непосредственных
   дочерних объектов**, а не всех потомков).
5. **Компания** = среднее прогресса её Целей. **Группа компаний** = среднее прогресса её Компаний.
6. Объекты с `progressMode = "recurring"` **исключаются из усреднения** и не имеют ползунка.
7. Пустой уровень (нет дочерних) даёт **0** (а не `NaN`); если все дочерние объекты повторяющиеся,
   берётся ручное значение родителя. Пересчёт всей цепочки вверх происходит мгновенно при любом
   изменении (прогресс, добавление, удаление, перенос, смена режима).
8. Отображается графически: кольцевая дуга вокруг объекта (всегда развёрнута к камере), полоса в карточке,
   мини-полоса и число в дереве, процент в метке, процент в поиске.

## 4. Режимы просмотра

Переключатель — **слайдер из трёх положений** и три отдельные кнопки-дубля:
**«Группа компаний» → «Цели» → «Проекты»**. Рядом кнопка **«Центрировать»**: камера плавно вписывает
все показанные объекты в экран (bounding sphere), а если объект один — ставит его точно в центр.

| Вид | Что рисуется | Кнопка добавления |
|---|---|---|
| Группа компаний | Компании-вселенные, связанные линиями с бегущей энергией | `+ Компания` |
| Цели | только галактики Целей выбранной Компании (или всех), связи с анимированным потоком энергии | `+ Цель` |
| Проекты | солнечная система выбранной Цели: Солнце → планеты-Проекты → спутники-Задачи → спутники-Подзадачи | `+ Проект` |

Данные общие для всех видов; выбор и состояние не теряются. «Центрировать» работает и для единственного объекта.

Контекстная кнопка в верхней панели добавляет **дочерний объект к выбранному**; если ничего не выбрано —
объект верхнего допустимого уровня для текущего вида. Созданный объект сразу сохраняется, выделяется,
центрируется и открывается в карточке.

## 5. Сцена и управление

* **Вращение сцены** — левая кнопка мыши; **зум** — колесо мыши (с ограничением min/max);
  **панорамирование** — правая кнопка мыши. Над панелями интерфейса колесо прокручивает панели
  и не «проваливается» в сцену (обработчик зума висит только на canvas).
* **Скорость вращения** — базовый период ближней орбиты ≈ 7 минут (`BASE_OMEGA = 2π / 420 c`), это в 4 раза
  медленнее исходной. Глобальный ползунок «Скорость» (0–2.0×) и кнопка «Пауза».
* **Спутники вращаются с той же угловой скоростью, что и родитель** — без ускорения на малых орбитах.
  При открытой карточке орбитальное движение замирает (эффекты пульсации продолжаются), после закрытия —
  возобновляется с того же места.
* **Клик по объекту** — открыть карточку; **клик по пустому месту** — снять выделение;
  **двойной клик** — фокус камеры на объекте.
* **Метки**: DOM-метки на слое поверх canvas, обновляются каждый кадр по мировой позиции объекта,
  показывают название и % прогресса. При пересоздании сцены, удалении и смене вида все старые метки
  удаляются (dispose), «зависших» подписей нет. При перегрузе метки далёких объектов скрываются
  и не накладываются друг на друга.
* **Выделение**: пульсирующее кольцо цвета объекта радиусом ≈ 1.45 × радиуса объекта, пульс ±10 %,
  кольцо — дочерний объект меша и движется по орбите вместе с ним.
* **Размеры и орбиты**: размер и диаметр орбиты меняются в карточке. Движок автоматически раздвигает орбиты:
  минимальный зазор между орбитами ≥ сумме радиусов соседних объектов + запас (60 % от максимального радиуса).
  Ручная настройка уважается, но не может нарушить зазор — значение «клэмпится» вверх, а подсказка
  под ползунком объясняет почему.
* **16 фактур** генерируются процедурно на Canvas при первом запуске (без внешних файлов), цвет объекта
  тонирует фактуру. «Сатурн» дополнительно получает кольцо.
* **Солнце (Цель)** — светящийся шар с пульсирующей короной и протуберанцами.
* **Компания/Группа** — светящееся ядро с 3 спиральными рукавами, звёздной пылью (`THREE.Points`).
* **Энергия**: связи между Целями и Компаниями — шейдерные линии с бегущими импульсами и частицами;
  направление задаётся свойством `flow` (`→`, `←`, `↔`).
* **Фон**: градиентные туманности, 2600 звёзд в объёме, мягкое свечение (аддитивные спрайты-короны).

### Поиск

Окно поиска — слева сверху. Ищет по мере ввода по названиям, описаниям, ФИО, ролям, функциям, ID,
статусам, типам свойств, срокам и ссылкам автоматизации, без учёта регистра и «ё/е».
Каждый результат показывает тип и путь (родитель → … → объект). Клик по результату переключает
нужный вид, центрирует камеру, открывает карточку и включает **«волшебное огненное кольцо»**
(шейдерные частицы пламени вокруг объекта, размер соответствует объекту). Кольцо гаснет при очистке
поиска, снятии выделения или выборе другого результата. Если совпадений нет — «Ничего не найдено».

### Правая панель «Структура целей Компании»

Раскрывающееся дерево всей иерархии с иконкой типа, цветом и прогрессом (мини-полоса + %) напротив
каждой строки, с цветовой индикацией по статусу. Клик по строке выделяет объект, при необходимости
переключает вид, центрирует камеру и открывает карточку; выбранная строка подсвечена и прокручивается
в видимую область. **Если объект не выбран, иерархия скрыта** — виден только заголовок с наименованием
Группы/Компании. При выборе дерево автоматически раскрывается до него. Через дерево можно переключаться
между Компаниями, Целями и Проектами.

## 6. Карточка свойств

Полупрозрачное окно, поля сверху вниз: название; родитель (тип + название, смена выпадающим списком
допустимых по иерархии объектов); тип свойства и статус; описание цели; прогресс (переключатель
«Ползунок прогресса / Повторяющаяся задача» и **ровно один** ползунок); ответственный (ФИО, роль, функция);
исполнитель (ФИО, роль, функция); срок; цвет, фактура (16 превью), размер, диаметр орбиты;
гиперссылки автоматизации (добавить / удалить / открыть в новой вкладке); связи и поток энергии;
кнопка «Добавить дочерний объект» с контекстным названием (`+ Компания / + Цель / + Проект / + Задача /
+ Подзадача`), «Удалить» (каскадно, с подтверждением) и «Закрыть»; ID (только чтение) и «Копировать ID».

Все правки применяются сразу и сохраняются. Пока карточка открыта, орбитальное вращение замирает.

## 7. Сохранение, экспорт, импорт, сброс

* Автосохранение в `localStorage` (ключ `orbital-okr:data`) с версионированием схемы (`version: 3`)
  и миграцией старых/битых данных; переживает перезагрузку и перезапуск браузера.
* **JSON** (кнопка «Экспорт JSON») — полный дамп (объекты, вид, UI-состояние, счётчики).
* **Импорт** — выбор файла `.json`; при ошибке показывается понятное сообщение, данные не портятся.
* **SQL** (кнопка «Экспорт SQL») — `CREATE TABLE` + `INSERT` для:
  `objects`, `object_people` (ответственные и исполнители), `object_links` (связи с направлением потока),
  `object_automation_links`, `object_sequence`. ID объектов сохраняются, кириллица экранируется,
  скрипт открывается и закрывается транзакцией `BEGIN; … COMMIT;`. Подходит для SQLite и PostgreSQL.
* **Сбросить БД** — с подтверждением возвращает демонстрационный набор (1 группа, 2 компании, 4 цели,
  13 проектов, задачи, подзадачи, разные статусы, ФИО/роли, ссылки, повторяющаяся задача, связи с энергией).

## 8. Отчёты

Кнопка **«Отчёты»** (рядом с «Сбросить БД») открывает выпадающий список. Первый пункт —
**«Обязанности сотрудника»**:

1. Модальное окно запрашивает ФИО с автодополнением по существующим сотрудникам
   (поиск без учёта регистра и «ё/е»; можно ввести часть ФИО).
2. Формируется стилизованная HTML-страница A4 (шапка, дата формирования, ФИО, роли, сводка:
   число объектов, средний прогресс, количество в риске и в просрочке).
3. Данные сгруппированы по ролям **«Ответственный»** и **«Исполнитель»**. Для каждого объекта:
   тип, название, развёрнутая иерархия пути (Группа → Компания → Цель → Проект → Задача → Подзадача)
   с отступами, статус, срок (просрочка выделена), достигнутый процент с графической полосой,
   функция сотрудника.
4. Кнопка **«Сохранить в PDF / Печать»** вызывает системную печать (`@page A4 portrait`, print CSS,
   панели интерфейса скрыты) — в диалоге выбирается «Сохранить как PDF». Кириллица отображается
   корректно, потому что PDF формирует сам браузер с системными шрифтами.
5. Кнопка **«Скачать HTML»** сохраняет автономный файл отчёта со встроенными стилями.
6. Если сотрудник не найден — понятное сообщение в модальном окне, пустой PDF не формируется.

Архитектура расширяемая: отчёт — объект `{ id, title, description, run }`, регистрируется через
`CosmoReports.register(...)` в `js/reports.js` и автоматически появляется в меню.

## 9. Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Esc` | закрыть карточку (и снять выделение) / закрыть отчёт / модальное окно |
| `Space` | пауза / продолжение вращения |
| `N` (или `Т`) | создать дочерний объект к выбранному |
| `H` (или `Р`) | центрировать камеру |
| `/` | перейти в поле поиска |
| `Enter` | в поиске — открыть первый/выделенный результат; в карточке названия — сохранить |

| `→` / `←` | в дереве — раскрыть / свернуть узел |

Мышь: ЛКМ — вращение, колесо — зум, ПКМ — панорамирование, двойной клик — фокус на объекте.

## 10. Допущения

* Корневая сущность — одна Группа компаний (демо-набор содержит одну). Кнопка `+ Компания` на виде
  «Группа компаний» создаёт компанию внутри неё; если группы нет — создаётся новая группа.
* Прогресс уровня считается как среднее **непосредственных** дочерних объектов (единое правило для всех
  уровней, см. п. 3).
* Связи (поток энергии) поддерживаются между объектами одного уровня — Целями и Компаниями; попытка
  связать объекты разных уровней отклоняется с понятным сообщением.
* Отчёт «Обязанности сотрудника» сопоставляет ФИО без учёта регистра и «ё/е»; при частичном совпадении
  выбирается первый подходящий сотрудник из подсказок.
* PDF формируется средствами браузера через печать HTML (самый надёжный путь для кириллицы);
  jsPDF со встроенными кириллическими шрифтами не используется, чтобы не тянуть base64-шрифты в офлайн-сборку.
* Фактуры процедурные (Canvas 2D), поэтому внешние изображения не нужны и приложение работает офлайн.
